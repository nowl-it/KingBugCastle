01

Method and tools

There is no plugin, no framework and no magic. The whole project is four kinds of evidence cross-checked against each other, plus one rule: when they disagree, the client wins.

Observed
TLS/HTTP traffic from the client, logcat, screenshots from a real device or emulator.
Declared
Master-data XML - what the game says its content is.
Compiled
libil2cpp.so + global-metadata.dat - what the game actually does.
Synthesised
A server that produces exactly the bytes the compiled layer expects, in the moment it expects them.

The toolchain is entirely unexceptional: Il2CppDumper (metadata → C# skeleton), Ghidra (decompiler), capstone (a few instructions at a time), UnityPy (asset bundles), apktool/apksigner/zipalign (client builds), ldd-free raw disassembly for the packer, and Python for everything else. Android devices were redroid instances, which matters later: they run ARM64 through a translator on x86_64, and that changes what a debugger can see.

Rule zero. The client is the specification. Any question the XML cannot answer ("does this field mean count or capacity?", "is this 0-based?") is answered by the function that reads it - never by a plausible guess.
02

The target: four layers

King God Castle is a Unity title (IL2CPP, ARM64) with a classic mobile-backend split. The useful mental model is that the client downloads its own content at boot, so the game is assembled from four independent layers, and each one fails differently.

LayerWhere it livesWhat it decidesHow it fails
ContentCDN XML bundle (AssetBundle)every number, string, stage, drop tablewrong text, missing content, gate says no
Codelibil2cpp.so + metadataall game logic, all invariantscrash, silent no-op, wrong panel
ProtocolHTTPS + AES bodieswhat the account ownsempty panel, null reference, stale state
TrustTLS pinning, anti-cheat, integritywhether the client runs at allinfinite loading, instant exit

Almost every wrong hypothesis in this project came from attributing a symptom to the wrong layer. A blank panel is layer 3; a blank panel that also freezes the UI is layer 2; a panel that never appears because the content is gated is layer 1.

03

Layer 1 - the master data

The client asks the backend for a patch folder, then downloads an xml bundle from the CDN. That bundle is a Unity AssetBundle containing a handful of TextAssets - plain XML, one file per table - plus an AssetHash.txt that names the bundle and its md5. 

GET /auth/getPatchFolder        → { "patchFolder": "172" }
GET /patch/172/AssetHash.txt     → xml:<md5hex>_<size>
GET /patch/172/xml               → AssetBundle( TextAsset: Skills, Units, Stages, … )

Extraction is therefore mechanical: download the bundle, load it with UnityPy, walk the TextAsset objects, write each m_Name to a file. Run that on every patch and you have a versioned corpus; that is what xml_history/ is - a pristine snapshot per patch, never edited, used as the diff base.

The edits the server actually serves live separately (server/xml_live/, plus a small replayable set of "mods" in code). That split matters: refreshing from the real CDN and applying local changes are two different operations, and the refresh must replay the mods or they vanish silently.

What is actually in the XML

Roughly 40 tables. The ones that carry most of the project: Units, Skills, Buffs, Stages, ShopItems, Gachas, InventoryItems, FixedAccessoryPresets, Treasures, ChallengeSeasons, and a localization table per locale (Strings_EN_US, Strings_VI, …).

Two structural facts are worth knowing before editing anything:

  • Skills are chains, not rows. A skill tier is a Skill that inherits from another via Inherit="id", frequently bouncing through TransformSkill / BuffAtCastSkill. One wrong Inherit produces a tier that silently uses the wrong base stats - no error anywhere.
  • Text is keyed, not inline. A unit's display name is a key like UnitName_10810 resolved through the Localizer at runtime. Any XML element that accepts a text key (e.g. <SubName>) can be pointed at an existing key to reuse text the developers never exposed.
The gotcha that cost ten attempts. A single XML comment (<!-- -->) anywhere inside a Strings_*.xml file makes Localizer.ParseTextAsset lose the entire locale: every Localize(key) then returns the raw key, so the whole game renders as SkillName_10800 instead of "Cathy". Comments are fine in Skills/Units/Stages - different parser. The bundle builder now refuses to run if it finds one, and that refusal is not to be bypassed.

Diffing a republish

Developers sometimes rewrite the same patch folder in place, so the folder name does not change and a naive "new folder?" watcher sees nothing. The reliable signal is the bundle's own md5 in AssetHash.txt. A row-level diff of the two XML sets answers "what actually changed" - and it is worth doing before reading the official patch notes, because the notes describe intent while the XML describes effect. One such diff surfaced a skill whose declared range grows from 3 tiles at tier 1 to 41 at tier 3 in the official data.

04

Layer 2 - the binary that isn't shipped

Up to v170 this was a solved problem: unzip the APK, take lib/arm64-v8a/libil2cpp.so and assets/bin/Data/Managed/Metadata/global-metadata.dat, feed both to Il2CppDumper. From v171 the file is simply absent. In its place is an anti-cheat library that, at startup, decrypts the game code into memory and maps it.

Finding the packer

The loader library's filename rotates every build - it has shipped as libaledatic.so, librolineng.so, libxenerene.so, libbisedich.so, liberallisi.so. Never key tooling on the name. Its SONAME is stable: libappsign4a.so. 

$ readelf -d lib/arm64-v8a/lib*.so | grep SONAME
  SONAME  [libappsign4a.so]          ← this is the loader

The unpack chain

The container is a header followed by layered transforms. In order: RSA-1024 (the payload key/signature block) → ChaCha20 (the stream) → LZ4 (the payload). Reversing that offline gives a plain ELF you can load, link and analyse. server/patchers/unpack_neo.py is that whole chain.

Producing the ELF is half the job. The loader also guards itself: a byte mismatch in its own code is fatal before unpacking, and the parser rejects an unexpected header. Those checks are the payload of the patch - twelve sites in the verified build:

GroupShapeCountWhy it fires
integritybl ; tbnz w0,#31,<fail>8code/segment hash mismatch after patching
parsermov w8,#-1 ; str w8,[sp,#0x94] ; b4header/format guard on the decrypted buffer

The second group is located by pattern (08008012 e89700b9 - exactly four hits in every loader seen), the first by table, and the tables differ per build and do not shift by a constant: libaledatic.so maps file offset == VMA, librolineng.so maps VMA == file − 0x4000, and the loader function itself grew between versions. Keying on "new offset = old offset + delta" is a guaranteed multi-hour detour.

Metadata must match libil2cpp exactly

IL2CPP does not resolve strings at runtime by name. It resolves them by index into the metadata's string-literal table, compiled into the code as an immediate. v171.0.01 inserted one literal at index 1545 of 25,730; that shifted 94% of all subsequent indices. Mixing a v171.0.01 binary with v171.0.00 metadata does not warn - it renders garbage text, or crashes in a place that has nothing to do with strings.

Practical consequence. A client build is a triple: binary, metadata, content bundle. Never mix triples. The build script derives all three from the same source directory for exactly this reason.
05

Layer 3 - reading compiled C#

Il2CppDumper gives a dump.cs that is a C# skeleton: class names, field offsets, method signatures, and for each method an RVA: line. That file is the index. It is not source, and it is never enough on its own. 

// dump.cs
public class PvPInfoResponseModel {
  // Fields
  public int semiSeason;        // 0x20
  public long[] seasonUntilAtDates; // 0x28
  // Methods
  public DateTime GetCurrentSeasonUntilAt(); // RVA: 0x2CC27FC Offset: 0x2CBE7FC
}

RVA, file offset, runtime address

script.json
ScriptMethod[].Address is an RVA in the same space as tombstone pc values.
File offset
RVA − 0x4000 for libil2cpp.so only. Other libraries differ; check, don't assume.
Runtime address
dlpi_addr from dl_iterate_phdr + the symbol's VMA. libil2cpp's first LOAD is at vaddr 0, so no fudge factor.
dump.cs "Offset"
Conveniently already equals RVA − 0x4000 - which is why some tools read it directly. Verify against one known-good patch before trusting it on a new build.

Reading a method by hand

A worked example, because this is the actual skill: GetCurrentSeasonUntilAt delegates to the property, which does 

seasonUntilAtDates[semiSeason - 1]

That -1 is the whole bug. With semiSeason = 0 the index is −1 → IndexOutOfRangeException inside a panel's MoveNext, which surfaces as "the PvP screen is broken and the cause is nowhere". Fix: send semiSeason ≥ 1 and a date array long enough to cover it. No client patch, no server hack - just the field the method actually reads.

The same reading is how the season panels were made to behave. Two related checks decide whether the game shows "pre-season" and blocks play: 

isPreSeason  = GetSeasonStartAt(0) > UtcNow      → nextSeasonStartAtDates[0] must be in the past
isBreakTime  = seasonUntilAtDates[semiSeason-1] <= UtcNow  → current end must be in the future

Both are just array values with day offsets. The fix was a table of offsets, not a code change - but only after reading the two predicates.

Field offsets, and ObscuredInt

`dump.cs` gives every field's offset, which is what makes a native hook viable: to read "player level" from a live object you need *(int*)((char*)obj + offset). Some fields are ObscuredInt, a 20-byte struct that must be read as a pair and decrypted through a thunk. Every UI read of e.g. CardData.potentialTier (offset 0xB8) follows that pattern, which is why a naive ldr w8,[x, #0xb8] yields nonsense.

06

Layer 4 - removing the gates

Four independent things stop a patched client from talking to you. All four are small once located; none are located by guessing.

a. Certificate pinning

Unity gives three certificate-validation paths, and a self-signed cert must survive all three. Each is a single method whose only correct answer is "yes":

Methodv171 file offsetPatch
PinnedCertHandler.ValidateCertificate0x2CB68D8mov w0,#1 ; ret
UnityTlsProvider.ValidateCertificate0x596EF64mov w0,#1 ; ret
MobileTlsContext.ValidateCertificate0x596D674mov w0,#1 ; ret

20008052 c0035fd6 = mov w0,#1 then ret. Four bytes of patch per method, and the whole TLS trust model of the client is gone.

b. Anti-cheat

XIGNCODE refuses to boot without a handshake with Wellbia. The approach is not to emulate the protocol but to replace the library: a stub .so that registers the same JNI entry points (ZCWAVE_*) as no-ops, answers /auth/xcdSeed with a seed-shaped value, and returns success to the integrity queries. The game then boots and never asks again.

That stub is also the project's only convenient place to run native code inside the process, so it grew into the hook host (section 8).

c. Host names - two passes, not one

Rebinding the API host by rewriting the il2cpp string literal table covers most URLs. Two do not live there: they are field/parameter default values, invisible to that walk, and the client quietly keeps talking to the real backend. 

pass 1  stringLiteral table      → every literal URL (same-length rewrite, CRC fixed)
pass 2  raw byte scan            → field-default URLs that pass 1 cannot see
verify    metadata scan for real host strings → must find 0

The verification step is the important one: "I patched it" is not evidence, "a scan finds zero real host strings" is.

d. Asset-bundle CRC

Custom bundle bytes can never produce the original CRC, and the catalog is part of the signed download. Editing the catalog to lie about the CRC corrupts the whole thing (invalid JSON, length repairs, every bundle fails). So the check itself is removed at runtime, at four sites:

v172 file offsetSitePatch
0x5FC5F10AssetBundleRequestOptions.get_Crcmov w0,wzr ; ret
0x5FC8484direct CRC argument (w1)mov w1,wzr
0x5FC639Cdirect CRC argument (w1)mov w1,wzr
0x5FC648Cdirect CRC argument (w2)mov w2,wzr
Every build patch is guarded. The patch script checks the expected original bytes at every site and aborts rather than corrupting the binary. This exists because one build once shipped a hand-patched library with 21 stray bytes - including a branch that overwrote a constant inside a state machine, turning a linear coroutine into infinite recursion. It was diagnosed twice as an "inherent IL2CPP bug" before anyone diffed the file against pristine.

e. The one patch that was wrong

Early on, 65 sites in the lobby's init were rewritten from ldr x0,[xR] to mov x0,xR, on the theory that a klass-pointer fixup never ran under the ARM translator. It ran. xR holds the GOT slot; the ldr is what loads the class pointer out of it. The rewrite left x0 pointing at the slot, so the static field read returned garbage and the singleton looked null - which is exactly the symptom the patch was supposed to fix. It stayed enabled for weeks because the lobby sometimes rendered anyway.

07

The protocol

The API is HTTPS with AES-128-ECB bodies and no meaningful header auth in practice for a local server. That simplicity is what made a full reimplementation feasible. 

key      a6072ad6b9c959ff           (16 ASCII bytes, AES-128-ECB)
padding  trailing spaces or zeros to a 16-byte multiple; decoder ignores the pad
request  raw ciphertext or ASCII-hex of it → header encryptedWithHex: true
auth     header accesstoken: <token>   (not Authorization: Bearer)
time     header = AES-hex("beforeLogin") pre-login, AES-hex(unix_ms) after

Which means a handler can be exercised without the game at all: 

KEY = b"a6072ad6b9c959ff"
def enc(d): raw = json.dumps(d).encode().ljust(16*((len(json.dumps(d))+15)//16), b" ")
            return AES.new(KEY, AES.MODE_ECB).encrypt(raw)
def dec(b): pt = AES.new(KEY, AES.MODE_ECB).decrypt(b)
            return json.loads(pt[:pt.rindex(b"}")+1])

The boot sequence is short and fully mapped: 

POST /auth/shake-hand            POST /auth/checkPatchVersion
GET  /auth/getPatchFolder        GET  /auth/xcdSeed        GET /auth/xcd
POST /auth/register | /auth/login     → AuthResponseModel { accessToken, seed, serverTime }
GET  /player  /player/currencies  /card/all  /deck  /treasure  /shop   … ~350 more

Route → model mapping, and the empty-model trap

`dump.cs` gives every request and response class; the work is joining the client's path strings to the right class. Where the join could not be proven, a name-similarity heuristic was used - and every wrong guess showed up as the same symptom: a null reference in a panel that received a valid-but-empty model. 

[RankingPanel.<ShowRanking>d__14.MoveNext]
  myRankingItem.Set(model.playerRank, true)   ← model.playerRank is null → NRE

So: unknown route → empty model → panel crash. The fix is not defensive client code; it is a real response. A handful of routes needed a direct handler registered before the generic loop, because the generic table mapped the path to the wrong model entirely (GET /post → a "receive" model with no posts field).

Closed vocabularies

Response strings are not free-form. RewardResponseData.type is compared against a fixed literal set - InventoryItem, Key, UnitExpItem, UnitSoulItem, CardSoul, Gold, Cash, Heart, Artifact, Treasure_*, Skin, NameTag, Flag… - and there is no "Item". An unmatched type does not error: the reward renders with no icon and a nonsense count. The server therefore keeps one internal vocabulary and translates once, at the wire boundary.

Related trap: Key is a ShopItem id, not an inventory id. ShopItem 370's <KeyItem> is inventory row 380; 70000 → 70005. Collapsing one into the other grants the wrong item, quietly.

Player state and invariants

Two planes, and the distinction explains most "I changed it and nothing happened" reports:

PlaneLives inChange latency
Account state / APISQLite, one row per player, read on every requestimmediate
Client master dataCDN xml bundlerebuild + restart + client re-download

Granting a treasure is plane 1. Making the treasure exist for the client is plane 2. Editing the wrong one produces a convincing no-op.

Invariants worth writing down

Two rules that were learned the hard way

Derive time, never store it. The lobby compares now against a tomorrow field and re-runs its whole fetch chain when the day turns. A stored tomorrow froze at account creation, so the day had "turned" permanently: the client re-logged in at 1 Hz - seventeen requests a second, no exception, no logcat entry, ~400k requests/day. It is now computed from the clock on every response.

Never infer an identity. "If no id, use the active save" is correct for a demo and catastrophic for a service: a client that lost its guest id got somebody else's world, with a session attached. The correct answer in multiplayer is a refusal. A new guest id gets a new save; an old save is re-attached deliberately, by name.

Runtime hooks

Some things cannot be fixed from the server: a stat that must be displayed, a mail body that must bypass the localizer. That is what the stub library is for - it hosts native code inside the running game.

Two mechanisms exist, and choosing wrong produces a hook that reports success and never fires.

methodPointer swapinline detour
Interceptsonly what Unity invokes via MethodInfo.methodPointerevery caller, including direct bl
Good forUpdate, Awake, OnEnableC#→C# calls, UI callbacks
Costone pointer writeprologue jump + executable trampoline
detour prologue (16 bytes)
  LDR  X17, #8
  BR   X17
  .quad target
trampoline
  <16 stolen bytes> ; jump back to target+16

The guard matters: if any of the four stolen instructions is PC-relative (ADR/ADRP/literal load/B/BL/conditional branch), it cannot be relocated and the hook must abort. Most prologues are stp/mov/sub sp and are fine.

Three silent failures, one session each. (1) The poll loop accepted the first dlopen("libil2cpp.so") handle - which was the packer, loaded long before the game, so every dlsym failed. Accept a handle only if it exports il2cpp_domain_get. (2) A /proc/self/maps scan filtered on r-xp found nothing, because guest ARM64 pages are mapped r--p and executed by the translator - use dl_iterate_phdr. (3) A diagnostic session wrapped three features in #if 0 and never restored it.
10

Content injection

Editing text is easy; making the client display something that was never authored is five separate problems. The worked example is a new hero costume.

1. The data row

A row in the unit/skin XML pointing at an asset name. Necessary, and by itself produces a blank thumbnail.

2. The bundle

Bundles are content-addressed and CRC-verified against a baked catalog. Custom bytes cannot match the CRC; the catalog cannot be edited. Therefore the runtime CRC check is removed (section 6d). Nothing else in the pipeline can work until this is true.

3. The atlas - geometry, not pixels

A character's battle animation is 19 frames in a fixed grid (130×140, five columns, the last bottom-right cell empty), and each frame carries a tight polygon computed for that silhouette plus a pivot-derived UV transform. Reusing a wider image inside the old mesh crops and zooms it: wrong pose, cut edges, bleed into the neighbouring cell. Every frame must be rebuilt as a four-vertex full-cell quad. 

verify: read back each serialized Sprite.image → must be exactly (130,140)
        reconstruct the atlas → must be byte-identical to the repository PNG

Frame 18 is special: it is the prefab's default Sprite and the skin's thumbnail, so it must be a front-facing standing idle with the full silhouette - not a run frame.

4. The prefab

Clone the source character: hierarchy, components, 10 animation clips, animator controller, and all PPtrs. Give the cloned sprites a distinct deterministic render-data key. Sharing the source's key resolves the portrait back to the original - or to nothing, with no error either way.

5. The addressables catalog

Five locations must be added, not one: texture + sprite for the battle atlas, texture + sprite for the illustration, and the prefab GameObject. Get four of five and the entry appears in the shop with a blank thumbnail and a default large portrait.

Ordering trap. The illustration bundle also needs full-rectangle render geometry - reusing the source's 908×912 tight polygon on a 1024×1024 portrait yields large transparent holes or a blank panel even though the texture and catalog entry are perfect.
11

Operations

Running it for strangers changes the problem from "does it work" to "does it keep working".

Ports
HTTP 8080 (game API after the TLS workaround), TLS 8443, admin 8081, player portal 8082.
Device
adb reverse tcp:80 tcp:8080 + adb reverse tcp:443 tcp:8443; hosts entries point the real domains at loopback.
Proxy
Caddy terminates TLS once for three hostnames and forwards to loopback; direct-IP requests have Cloudflare headers stripped so nobody can forge the client address.
Deploy
A key whose authorized_keys line pins one command: refuse-if-dirty → git pull --ff-only → restart units.
CI
Full pytest on push; a separate workflow builds the patched client and publishes a release.
Cost
Zero, by requirement. That is why the 1.1 GB stock package is fetched from GitHub during a build and deleted after: egress is billed, release assets are not.

Two operational failures worth naming. First, the daily-reset loop (section 8) - a service problem caused by a data-model decision. Second, "the deploy did nothing": the units redirect their output to files in /tmp, not journald, so a restart that appeared to fail had actually succeeded and a config change that appeared to apply had not. Read the file the process actually writes.

The debugging method

This is the part worth taking to another project, because it generalises and it is what turned multi-session rabbit holes into hour-long fixes.

a. Turn a managed exception into a real fault

An IL2CPP NullReferenceException reports a method and no line. Temporarily NOP the null-check branches inside the suspect method; the first null object then falls through into its own dereference and SIGSEGVs at a locatable PC. 

#00 0x03040134  GameManager$$Init      +0x98  ldrb w8,[x19,#0x1b0]   x19 == 0
#01 0x034E5624  Scene_Lobby$$Init      +0x270 bl GameManager.Init
#02 0x034E368C  Scene_Lobby$$Awake     +0x6E0

That is a root cause with coordinates. It is also how the wrong patch in section 6e was proven wrong: at the same instant, a healthy singleton was readable through the normal path.

b. Find callers by scanning for BL

When the question is "who calls this endpoint", resolve the endpoint's C# entry point, then scan the binary for branch-link instructions targeting its RVA - no decompiler needed: 

(w >> 26) == 0x25  →  imm26 = w & 0x3FFFFFF, sign-extend → target = site + imm*4
file offset = target - 0x4000

Two hops of that found the 1 Hz login loop: POST /auth/login ← RestAPI.Login ← Scene_Lobby.Update.

c. Distrust every "it worked"

ClaimWhat actually proves it
"hook installed"the handler logged a call
"hosts patched"a metadata scan finds zero real host strings
"asset injected"each sprite reads back as 130×140 and the atlas reconstructs identically
"route answered"the panel renders on a device
"the binary is patched"it diffed to exactly the three intended sites and nothing else

d. Check the environment before the code

The "Loading resources…" hang was not a network bug: the client's HTTP helper had grown an analytics call, and analytics initialisation throws on a device without Play Services. The request went out, the response arrived, the callback died mid-flight. Two ret stubs fixed it. In an emulator or a stripped-down environment, the platform is a layer too.

And the meta-rule. Fabricating a plausible explanation is worse than saying "I don't know yet" - one costs an hour, the other costs a week. Every long detour in this project started with a confident sentence nobody had verified.
Closing

What the full record comes to

Nothing in here is advanced. There is no clever algorithm, no novel technique, no exploit research. It is a sequence of ordinary skills applied in the right order, with one discipline on top: verify against the layer that cannot lie.

The game is not the hard part. The hard part is believing the evidence instead of the explanation.
